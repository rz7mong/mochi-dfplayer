Panduan Mochi DFPlayer

Untuk firmware v0.6.8: 14 klip di flash (6 gundam, 5 mochi, 3 dasai), suara MP3 dari DFPlayer Mini. Belum ada pemasang lewat browser. Jangan pakai installer mochi-rzmong: itu firmware amplifier I2S (MAX98357), bukan DFPlayer.

Sensor sentuh: firmware membaca GPIO1 dengan pull-up internal, jadi tersentuh/tertekan = LOW. TTP223 bawaan pabrik keluarannya HIGH saat disentuh, dan alat akan mengira disentuh terus. Solder jembatan pad A di TTP223 supaya aktif LOW. Tombol tekan biasa cukup disambung antara GPIO1 dan GND.

3. Upload firmware

Pakai PlatformIO. Klip JPEG dibuat jadi header saat build oleh skrip Python yang butuh Pillow.

  1. Pasang Python 3 dan Git.
  2. Pasang PlatformIO dan Pillow: 
    python3 -m venv ~/.piovenv
source ~/.piovenv/bin/activate        # Windows: %USERPROFILE%\.piovenv\Scripts\activate
pip install platformio pillow
    Kalau memakai ekstensi PlatformIO di VS Code, pasang Pillow ke Python PlatformIO: ~/.platformio/penv/bin/pip install pillow (Windows: %USERPROFILE%\.platformio\penv\Scripts\pip install pillow).
  3. Ambil repo: 
    git clone https://github.com/rz7mong/mochi-dfplayer.git
cd mochi-dfplayer/firmware
  4. Colok Super Mini lewat USB-C, lalu hapus flash penuh dan upload. Hapus penuh perlu sekali, karena tabel partisi berubah (satu app 0x3F0000, tanpa spiffs) dan sisa firmware lama bisa mengganggu: 
    pio run -e esp32-c3-dfplayer -t erase
pio run -e esp32-c3-dfplayer -t upload
    Upload berikutnya cukup pio run -e esp32-c3-dfplayer -t upload.
  5. Lihat log (opsional): pio device monitor -b 115200. Saat nyala muncul DFPlayer siap, MPU6050 siap, lalu model 7/14 mochi/full1 trek 19.

Build memakai sekitar 91% flash app (3,77 MB dari 4,13 MB). Port serial lewat USB CDC bawaan, bukan UART0.

4. Kartu microSD

Format FAT32 (MBR, satu partisi). Semua berkas di root, tanpa folder.

Penting: firmware memanggil trek dengan nomor (perintah play(n) DFPlayer). DFPlayer menghitung nomor itu dari urutan berkas disalin ke kartu, bukan dari nama berkas. Karena nomor trek dimulai dari 19, kartu harus berisi 0001.mp3 sampai 0040.mp3, disalin berurutan ke kartu yang baru diformat. Trek yang tidak dipakai cukup diisi MP3 hening pendek.

Membuat MP3 hening dan menyalin berurutan (Linux/macOS, perlu ffmpeg; folder suara/ berisi 14 MP3 di atas):

ffmpeg -f lavfi -i anullsrc=r=44100:cl=mono -t 0.3 -q:a 9 hening.mp3
for i in $(seq 1 40); do f=$(printf %04d $i).mp3
  [ -f suara/$f ] || cp hening.mp3 suara/$f; done
for i in $(seq 1 40); do cp suara/$(printf %04d $i).mp3 /media/KARTU/; sync; done

Di Windows, salin satu per satu berurutan, atau rapikan urutan dengan DriveSort. Hapus berkas tersembunyi macOS (._*, .Spotlight-V100) karena ikut terhitung.

Suara diulang dari awal setiap klip berulang, jadi MP3 yang lebih panjang dari klipnya akan terpotong. Volume dipasang 28 dari 30 setiap trek mulai.

5. Cara pakai

  • Nyala: langsung memutar mochi full1 (model 7) dengan suara 0019.
  • Ketuk singkat: berhenti (layar hitam, lampu latar mati, suara berhenti) atau putar lagi. Ketukan dijalankan sekitar 0,35 detik setelah dilepas, untuk menunggu kemungkinan ketuk dua kali.
  • Ketuk dua kali (dalam 0,35 detik): model berikutnya. Setelah model 14 kembali ke model 1.
  • Tahan (≥ 0,4 detik, saat memutar): klip "tahan" tema itu berulang sampai dilepas, lalu kembali ke klip semula di frame yang sama.
  • Goyang tiga hentakan dalam 1 detik (saat memutar, perlu MPU6050): klip goyang diputar sekali, lalu kembali. Jeda 1 detik sebelum goyang berikutnya terdeteksi.

Gundam dan mochi 240×240 penuh layar. Dasai 240×120 di tengah dengan pita hitam atas-bawah. Tempo: gundam 90 ms, mochi 100 ms, dasai 40 ms per frame. Durasi di atas adalah durasi target; bisa sedikit lebih lama jika decode JPEG lebih lambat dari tempo itu.

6. Kalau ada masalah

GejalaPeriksa
Layar hitam, lampu latar matiBLK ke GPIO7. Alat mungkin sedang berhenti: ketuk sekali. Kalau sentuh dibaca terus (TTP223 belum aktif LOW), alat tidak merespons dengan benar.
Layar menyala putih/hitam tanpa gambarSCL GPIO4, SDA GPIO6, DC GPIO3, RES GPIO10. CS modul harus ke GND. VCC 3V3. Pastikan modul ST7789 240×240, bukan 240×320 atau ST7735.
Warna terbalik (negatif) atau merah/biru tertukarDi firmware/include/User_Setup_ST7789.h: hapus TFT_INVERSION_ON (ganti TFT_INVERSION_OFF) untuk warna negatif; ganti TFT_RGB_ORDER TFT_BGR ke TFT_RGB untuk merah/biru tertukar. Upload ulang.
Gambar bergeser atau ada garis di tepiModul dengan offset lain. Coba hapus CGRAM_OFFSET di berkas yang sama.
Tidak ada suaraLog DFPlayer tidak jawab berarti UART: RX DFPlayer ← GPIO20 (lewat 1 kΩ), TX DFPlayer → GPIO21, VCC 5V. Kartu FAT32, berkas di root, berurutan 0001–0040 (lihat bagian 4). LED DFPlayer menyala saat memutar.
Suara klip salahUrutan salin di kartu tidak sesuai nomor. Format ulang dan salin 0001–0040 berurutan.
Bunyi letup, ESP reset saat suara mulaiDaya USB kurang: pakai kabel/charger lebih baik, tambah kapasitor 100–470 µF di VCC DFPlayer.
Animasi lambat atau patahNormal sedikit untuk dasai (40 ms per frame). Pastikan SPI_FREQUENCY 40 MHz tidak diturunkan. Kabel LCD pendek. Klip baru: kecilkan ukuran atau naikkan --step.
Goyang tidak bereaksiLog MPU6050 tidak ada: periksa SDA GPIO8, SCL GPIO9, VCC 3V3, alamat 0x68. Goyang harus kuat, tiga hentakan dalam 1 detik.
Upload gagal / port tidak munculPakai kabel USB data. Tahan BOOT, colok USB-C, lepas BOOT, lalu upload ulang. Linux: tambahkan user ke grup dialout. Tutup monitor serial lain.
Build gagal No module named PILPasang Pillow ke Python yang dipakai PlatformIO (bagian 3).
Build gagal karena ukuran appKlip terlalu besar untuk app 0x3F0000. Kurangi klip, kualitas, atau frame.

7. Menambah atau mengganti klip

Klip disimpan di firmware/assets/builtin/jpeg/<tema>/<nama>.mjpeg + .json, dibuat tools/import_jpeg_clip.py, lalu didaftarkan di firmware/assets/meta.json. Saat build, tools/embed_jpeg.py menanam semuanya ke include/jpeg_clips.h.

  1. Siapkan sumber: header C berisi frame JPEG, folder *.jpg/*.png (misalnya hasil ffmpeg -i video.mp4 -vf fps=12,scale=240:240 f/%04d.png), atau GIF.
  2. Impor dari folder firmware (perlu Pillow; jpegtran opsional untuk optimasi lossless): 
    python3 tools/import_jpeg_clip.py mochi senyum f/ --delay 80 --quality 80
python3 tools/import_jpeg_clip.py gundam tembak tembak.gif --smooth 1.2 --quality 82
python3 tools/import_jpeg_clip.py dasai video05 video05.h --resize 240x120 --quality 80 --delay 40
    Opsi: --delay ms per frame, --step N ambil 1 dari N frame (hemat flash, tempo tetap), --quality JPEG (disarankan ≥ 75), --resize WxH Lanczos + tajam ringan, --crop WxH, --smooth hilangkan dither GIF. Klip lebih kecil dari 240×240 digambar di tengah.
  3. Daftarkan di meta.json bagian "jpeg_clips": ["tema", "nama", peran, trek]. Peran "" biasa, "dizzy" diputar saat goyang, "heart" saat tahan (satu per tema). Trek = nomor MP3; kalau dikosongkan, diberi nomor berikutnya otomatis. 
    ["mochi", "senyum", "", 24]
    Klip baru masuk setelah klip lain di temanya; tema baru ditaruh di akhir urutan. Tema saat nyala diatur "boot_theme".
  4. Mengganti klip: impor ulang dengan tema/nama yang sama (berkas ditimpa). Menghapus: buang barisnya dari jpeg_clips dan hapus berkasnya.
  5. Build dan upload, lalu tambahkan MP3-nya ke kartu (ingat urutan salin).
